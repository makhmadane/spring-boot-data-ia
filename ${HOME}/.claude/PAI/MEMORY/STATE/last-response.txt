## Ce qui a été fait

**Corrections préalables**
- `application.properties` avait un caractère non-UTF8 qui cassait la compilation (`filtering ... failed with MalformedInputException`) — corrigé.

**Relation manquante corrigée**
- `Assurance.type` (`@ManyToOne`) ajouté — l'assurance est désormais rattachée à un `Type` (`type_id` en DB, nullable, `ddl-auto=update` le créera automatiquement).

**Nouveaux packages**
- `dto/request/` : `AssuranceRequest`, `TypeRequest` — validation via `@NotBlank`, `@Positive`
- `dto/response/` : `AssuranceResponse`, `TypeResponse` — mapping via méthode statique `from(entity)`, jamais l'entité JPA exposée directement
- `service/` : `AssuranceService`, `TypeService` — toute la logique métier + `@Transactional`, plus de repository appelé depuis un contrôleur
- `exception/` : `ResourceNotFoundException`, `ApiError` (record), `GlobalExceptionHandler` (`@RestControllerAdvice`) — 404 propre pour ressource introuvable, 400 avec détail champ-par-champ pour échec de validation
- `controller/api/` : `AssuranceApiController` (`/api/assurances`), `TypeApiController` (`/api/types`) — CRUD complet avec `ResponseEntity`, codes HTTP corrects (201 + `Location` sur POST, 204 sur DELETE, 404 automatique via l'exception), pagination native (`Pageable` → `?page=0&size=10&sort=nomClient`)
